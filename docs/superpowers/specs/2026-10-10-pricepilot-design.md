# PricePilot design

Purpose: a distributor or small ecommerce operator can turn recurring supplier price lists into reviewed catalogue updates and import-ready CSV files. User requested a complete, tested Next.js + Supabase app and immediate implementation; design questions are waived.

Builder decisions: one private workspace per authenticated account; USD default with selectable ISO currency; supplier-specific exact SKU aliases; single currency per workspace; CSV and XLSX only, 5 MB upload limit and 5,000 data rows. No fuzzy automatic matching, OCR/PDF, live store writes, billing, team invitations, or claims of paying customers. These can follow validated buyer needs.

Workflow: sign in/register/reset password; dashboard with real counts; manage supplier name, markup or target gross margin, percentage, currency, increase-warning threshold, saved column mapping and SKU aliases. Import existing catalogue (sku/name/cost/selling price) with validation. New supplier update: upload, select sheet, map SKU/name/cost columns, preview, save mapping and persist batch. Match exact trimmed case-insensitive SKU or supplier-approved alias; unknown products require explicit new-product approval. Duplicate SKUs, conflicting aliases, invalid costs, and ambiguous prices are blocked. Missing supplier products reported, never deleted. Price increases and margin problems visible; approval does not silently ignore blocked rows. Approval stores chosen row IDs; apply is atomic and idempotent, prevents stale catalogue overwrites using a workspace revision, and preserves history and change report. Export includes approved valid rows only. Report CSV includes every row and issue.

Prices use decimal arithmetic and integer cents; distinguish markup vs gross margin. Round selling price upward to nearest cent to preserve margin. No mixed currency conversion. Locale-aware parsing via explicit decimal separator; preserve leading-zero SKUs; never evaluate formulas. CSV exports neutralize spreadsheet formula injection. Sensitive files parsed client-side, only normalized data persisted; no raw upload storage.

Architecture: Next.js App Router and server actions; Supabase Auth and Postgres with RLS, no service key in application. SQL RPC performs atomic workspace saves with optimistic versioning; data JSONB stored per account with strict shape validation in TypeScript and SQL constraints. State contains suppliers, products, batches and revision; acceptable for bounded first release, no claim of unlimited scale. Domain modules are framework-independent and use discriminated review statuses. Supabase token verified server-side. Browser demo explicitly labelled browser-local; supports same workflow without credentials and never impersonates cloud persistence.

UX: warm off-white canvas, dark ink and emerald accents, readable tables, large labels, progress stepper, obvious warnings and empty states. Sidebar dashboard/suppliers/catalogue/history. Keyboard accessible forms and controls, responsive mobile layout, visible loading and recoverable error states.

Verification: test-first monetary, parsing, matching, approval and persistence logic; real local Supabase auth/RLS/concurrency tests; browser full workflow and authentication, reload persistence, error paths, accessible controls and mobile layout; TypeScript, ESLint, production build and dependency audit. Report actual checks and limits. Hosted deployment needs user's Supabase project and hosting; local running application is the deliverable in this workspace.
